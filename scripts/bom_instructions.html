Filling in the BOM template

MRP-lite · DT Solutions Ltd · adding the missing Bills of Materials

A BOM (Bill of Materials) lists which materials go into making one unit of a product, and how many of each. 37 products currently have no BOM, which is why material planning can’t run for them yet. This template lets you add them in, then load them into the system.

Open this file in Excel
C:\Users\conta\OneDrive\Desktop\NEw manager\MRP-lite\scripts\bom_template.xlsx

Step by step

  1. Open the file above in Excel and go to the “Enter BOMs” tab.
  2. The 37 products that need a BOM are already listed in column A (Product Code), with their names filled in next to them.
  3. For each product, fill the two yellow columns:
    • Material Code — click the cell and pick from the dropdown (only valid codes are allowed, so no typos).
    • Qty per Unit — how many of that material are needed to make one of the product.
  4. The grey Material Name column fills in by itself so you can double-check you picked the right material.
  5. Product needs more than one material? Add a new row underneath, put the same product code again, then the next material and quantity. Repeat for as many materials as the product needs.
  6. Don’t know a product’s BOM yet? Leave it blank and come back to it later — you don’t have to do all 37 at once.
  7. Save the file (keep the name bom_template.xlsx).
The two reference tabs help you: the “Materials” tab lists every material code, name, unit and supplier; the “Products” tab lists the 37 products that still need a BOM.

Loading it back into MRP-lite

When you’ve filled in some or all of it, open a terminal in the project folder (with the virtual environment active) and run:

# 1. Preview only - checks everything, writes nothing
python scripts/import_boms.py --dry-run

# 2. Actually import the BOMs
python scripts/import_boms.py

# 3. Refresh the saved data snapshot
python scripts/export_db.py
It’s safe to work in batches. The importer checks every row before writing anything — if a code or quantity is wrong it tells you exactly which row to fix and changes nothing. And re-running it updates instead of duplicating, so you can do a few products today, import, do more tomorrow, and import again.
